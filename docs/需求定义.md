# AI-UK 智能提词器 · 需求定义

> v0.3 · 2026-08-09 · 所有结论均经用户确认，本文为开发基准。

---

## 1. 这是什么

老K 自用的 Mac + iPhone 双端提词器。

**一句话**：打开 → 粘贴文案 → 点开始 → 念，提词器听着你的语速自动滚动，手机不发烫。

**性质**：ai-lab 实验域项目。功能成熟后再考虑沉淀到正式域。

---

## 2. 核心使用流程

这是唯一主链路，所有设计决定以此为基准：

```
① 打开 App → 看到文案输入框（首页首屏，最显眼的操作区）
② 粘贴或输入口播文案
③ 点击「开始」
④ 提词器开始监听你的声音
   ├─ 你在说话 → 文案自动匀速滚动，语速快滚动快、语速慢滚动慢
   └─ 你停下来 → 滚动暂停，等你继续
⑤ 念完，手动停止 → 录制结束，视频保存到相册/本地
```

**这条流程的关键原则：**

- 文案输入框必须是**首页首屏最突出的入口**，不是藏在菜单里的功能——打开就能粘贴
- 启动后用户只管念，不对提词器做任何手动操作——这是语音跟随的价值
- 提词文字浮在摄像头画面上方（背景半透明），念稿时能看到自己的表情
- 整个过程手机不能发烫——录制规格保守，优先降低编码压力

## 3. 功能范围

### P0 · 第一批必须有（9 项，按使用流程分组）

**输入**
- [ ] 文案输入入口：首页首屏大文本框 + 粘贴按钮，支持长文

**显示**
- [ ] 提词滚动：大字、中文优先、可调字体大小、可调滚动速度基线的窗口大小可拖拽调整（适应 Mac 大屏 / 笔记本 / iPhone 不同尺寸）
- [ ] 背景透明度可调：透明度滑块，让底层摄像头画面透过文字层可见
- [ ] 窗口可拖拽调整尺寸

**智能**
- [ ] 语音跟随：检测说话状态，说话时自动滚动，停顿时自动暂停
- [ ] 语速调速：语速快滚动快、语速慢滚动慢，平滑过渡，不突变

**录制**
- [ ] 摄像头画面预览（念稿时看到自己）
- [ ] 录制并保存视频：iPhone 存相册 / Mac 存本地
- [ ] 双端各自独立运行，无需服务器

### P1 · 第二版

- [ ] 讲稿库管理（多条稿子、分类、最近使用）
- [ ] 设置记忆（上次的字体大小、速度基线、透明度，打开自动恢复）
- [ ] 手动微调覆盖（语音跟随不准时，可手动调速纠正）

### P2 · 打磨

- [ ] 录制规格可选 720p（减缓发热）
- [ ] 导出视频规格选择
- [ ] 暗色模式 / 护眼
- [ ] 讲稿同步（iCloud / 手动传输，可选）

## 5. 已确认的设计决策

| 维度 | 结论 |
|---|---|
| 使用场景 | 录制视频 / 口播（非线下演讲） |
| 双端形态 | Mac 和 iPhone 各自独立完整使用 |
| 核心能力 | 语音跟随：自动启停 + 按语速调速 |
| 讲稿语言 | 中文为主 |
| 成片字幕 | 不需要，成片画面干净 |
| 解决的核心痛点 | ① 手机录制+提词同时跑发热卡顿 ② 免费版限次（每天1次/3分钟）③ 不想付费 ④ 想自己用 AI agent 造 |

## 6. 技术方案

### 路线

**浏览器原型 → SwiftUI 原生**（行业标准做法：先用低成本原型验证最高风险点，验证通过再投入原生开发）

| 阶段 | 内容 | 耗时 | 退出标准 |
|---|---|---|---|
| Phase 1 · 浏览器原型 | WebRTC + Web Speech API 可交互原型 | 2–3 天 | Mac/iPhone 真机能跑，语音跟随手感可用 |
| Phase 2 · 原生 MVP | SwiftUI + Apple Speech + AVFoundation | 1–2 周 | 双端可独立录制口播、导出视频 |
| Phase 3 · 打磨 | 发热优化、稿库、设置记忆 | 持续 | 发热改善、日常使用无碍 |

### 各层技术选型

| 能力 | 浏览器原型 | 原生版 |
|---|---|---|
| 相机/麦克风 | WebRTC（getUserMedia） | AVFoundation |
| 中文语音识别 | Web Speech API | Apple Speech（本地、不联网） |
| 提词渲染 | DOM + CSS | SwiftUI |
| 录制 | MediaRecorder → WebM | AVCaptureSession → MP4 |
| 存储 | 本地临时文件 | iPhone 相册 / Mac 文件系统 |

### 语音跟随算法

这是整个项目最高风险、最需要验证的部分：

```
麦克风 → 实时语音识别（中文）→ 识别文字与讲稿逐句对齐
  ├─ 有识别结果 → 判定"正在说话"→ 按当前语速（字/秒）比例推进滚动
  ├─ 无识别结果持续 N 秒 → 判定"停顿"→ 暂停滚动
  └─ 恢复识别 → 重新对齐，继续滚动

调速逻辑：语速（字/秒）↔ 滚动速度（像素/秒）→ 线性映射 + 平滑插值
```

**原型阶段重点验证 4 个点：**
1. 中文识别在 iPhone Safari 上的延迟（预期 0.3–1s，可接受）
2. 停顿判定阈值 N 取多少合适（过长卡顿、过短误停）
3. 语速变化时滚动速度的平滑度（突变会晕）
4. 识别文本与讲稿的对齐策略（逐句匹配 vs 关键词匹配）

## 7. 风险和应对

| 风险 | 等级 | 应对 |
|---|---|---|
| 中文语音识别在手机端延迟/准确率差 | 高 | Phase 1 真机实测决定是否继续原生路线；预留手动调速兜底 |
| 停顿判定不跟手 | 高 | 原型阶段用真实口播内容测试调参 |
| 手机录制+识别仍发热 | 中 | 录制规格降到 720p；原生版用本地识别模型，不联网 |
| 原生版部署门槛（Xcode/签名） | 中 | 免费 Apple ID 可自签部署到自己手机；提供操作文档 |
| iOS Safari 对 Web Speech 支持差异 | 中 | 原型阶段直接测出来；原生版不受此影响 |
